# 物流追踪自动化项目 - 需求文档

## 1. 系统目标

自动追踪公司所有 Amazon FBA 货件的物流状态，及时向负责人推送异常信息，减少人工逐个查询货代网站的工作量。

## 2. 核心功能模块

### 2.1 数据导入模块

| 项目 | 说明 |
|------|------|
| 功能 | 从 Excel 读取货件信息导入数据库 |
| 输入 | Excel 主表（"发货数据详情" sheet，header 在第 2 行，数据从第 3 行开始） |
| 输出 | PostgreSQL `logistics_shipments` 表 |
| 触发 | 每次程序运行时执行 |
| 数据量 | 取决于 Excel 行数（通常几百到上千条） |

**字段映射**（15 个 Excel 列 → 数据库字段）：
- 发货ID → shipment_id（主键）
- 货运单号 → tracking_no
- 货代 → forwarder
- 店铺 → shop_name
- 站点 → site
- 货件编号 → fba_id
- FBA仓库 → fba_warehouse
- 负责人 → manager_name
- 货件在途状态 → status
- 货件状态备注 → latest_info
- 船名航次 → vessel_voyage
- 开船/起飞日期ETD → etd
- 到港时间（ETA）→ eta
- 妥投日期 → signed_at
- 是否有被查验 → is_inspected

### 2.2 物流爬取模块

| 项目 | 说明 |
|------|------|
| 功能 | 从 8 家货代自动抓取物流轨迹 |
| 输入 | 货运单号（tracking_no） |
| 输出 | 物流状态、时间、船名、查验标记等 7 个字段 |
| 爬取范围 | 仅爬取未签收且有货运单号的货件 |

**爬取结果字段**（7 个）：
1. status — 货件在途状态
2. latest_info — 最新的物流状态描述
3. vessel_voyage — 船名航次
4. etd — 开船日期
5. eta — 到港日期
6. signed_at — 妥投日期
7. is_inspected — 是否被查验

### 2.3 状态变更通知模块

| 项目 | 说明 |
|------|------|
| 功能 | 物流状态变化时实时通知负责人 |
| 输入 | 新旧状态对比结果 |
| 输出 | 钉钉机器人私聊消息 |
| 触发 | 每条货件状态变化时立即触发 |

**通知内容**：单号 + 店铺 + 发货ID + 新状态

### 2.4 异常分析模块

| 项目 | 说明 |
|------|------|
| 功能 | 检测延期/查验/延误货件 |
| 输入 | 待处理任务列表（未签收货件） |
| 输出 | 分类异常清单 |
| 触发 | 爬虫完成后执行 |

### 2.5 异常推送模块

| 项目 | 说明 |
|------|------|
| 功能 | 按负责人聚合异常并推送钉钉 |
| 输入 | 异常清单 |
| 输出 | 钉钉私聊消息 |
| 路由 | US 站异常发给 US 站管理员；其他按负责人分组发送 |

### 2.6 数据回写模块

| 项目 | 说明 |
|------|------|
| 功能 | 将更新后的数据写回 Excel |
| 输入 | 数据库查询结果 |
| 输出 | 更新后的 Excel 文件 |
| 写入列 | AY(ETD), AZ(妥投), BC(状态), BD(备注), BE(ETA), BL(船名), BG(查验) |

## 3. 业务规则

### 3.1 爬取范围
- 仅爬取 **未签收**（`status != '签收'`）且有 **货运单号**（`tracking_no IS NOT NULL`）的货件
- 已标记为 `Done` 的货件跳过

### 3.2 异常判定规则

| 异常类型 | 判定条件 | 分组方式 |
|----------|----------|----------|
| 延期 | 当前日期 - ETA > 5 天 | US 站单独一组；其他站按负责人分组 |
| 查验 | `is_inspected == True` | 按负责人分组 |
| 延误 | `latest_info` 包含"延误"、"延迟"或"延至" | 按负责人分组 |

### 3.3 状态变更判定
- 按 `'————'` 分隔符取状态文本的第一段进行对比
- 新旧第一段不同且新值不为空 → 视为变更
- 变更时立即通过钉钉机器人发送私聊通知给对应负责人

### 3.4 通知路由
- 每个负责人映射到钉钉用户 ID（配置在 `.env` 的 `MANAGER_MAPPING` 中）
- US 站异常通知发送给 `US_SITE_MANAGER` 列表中的所有用户
- 其他异常按负责人分组，通过 `MANAGER_MAPPING` 查找钉钉 ID 发送

## 4. 数据源

| 数据源 | 类型 | 更新频率 | 说明 |
|--------|------|----------|------|
| 发货流程表 Excel | 主数据源（钉钉在线表格快照） | 每次运行前人工下载 | 唯一数据源 |
| 货代网站 ×5 | Playwright 浏览器自动化 | 每次运行 | 袋你飞、海桥、心达、丛林鸟、易派 |
| 纽酷 API | REST API + JWT 认证 | 每次运行 | Token 缓存 24 小时 |
| 辰舟/欧杰 Excel | 本地 Excel 文件 | 每次运行 | 含背景色判断（黄色=已送达） |

## 5. 运行环境

| 项目 | 要求 |
|------|------|
| Python | 3.9+ |
| 数据库 | PostgreSQL（数据库名 `tracking`） |
| 操作系统 | Windows（`dingtalk_automation.py` 依赖 pywinauto/pyautogui） |
| 浏览器 | Playwright Chromium（需 `playwright install chromium`） |
| 钉钉 | 未企业认证，Excel 文件需人工下载/上传 |

## 6. 配置项

所有配置存储在 `.env` 文件中，通过 `config.py` 加载：

| 配置项 | 说明 |
|--------|------|
| DB_HOST / DB_PORT / DB_NAME / DB_USER / DB_PASSWORD | PostgreSQL 连接信息 |
| DINGTALK_APP_KEY / APP_SECRET / ROBOT_CODE | 钉钉机器人凭证 |
| MANAGER_MAPPING | JSON 格式，负责人名 → 钉钉用户 ID |
| US_SITE_MANAGER | JSON 数组，US 站管理员钉钉 ID 列表 |
| DAINIFEI_USERNAME / PASSWORD | 袋你飞登录凭证 |
| HAIQIAO_USERNAME / PASSWORD | 海桥登录凭证 |
| CLN_USERNAME / PASSWORD | 丛林鸟登录凭证 |
| XINDA_USERNAME / PASSWORD | 心达登录凭证 |
| NIUKU_USERNAME / PASSWORD | 纽酷登录凭证 |
| MAIN_EXCEL_PATH | 主 Excel 文件路径 |
| CHENZHOU_FILE_PATH | 辰舟 Excel 文件路径 |
| OUJIE_FILE_PATH | 欧杰 Excel 文件路径 |
| HEADLESS | 是否无头模式运行浏览器 |
| TIMEOUT | 超时时间 |
| RETRY_COUNT | 重试次数 |
